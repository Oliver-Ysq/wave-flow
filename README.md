# Wave Flow

**让任务有章可循，让不同 Agent 发挥所长。**

Wave Flow 是一个本机运行的 AI Agent 工作流桌面应用。用对话描述目标，让主控提出方案；确认后，由真实的 Codex / DeepSeek Harness / Claude Code Agent 分阶段执行（Kimi CLI 支持已暂时下线，历史记录仍可查看），你可以随时查看进度、回答问题或停止任务。

把任务交给可控的流程，把不同工作交给合适的 Agent。不必让一段越来越长的对话，承担从规划到交付的所有事情。

## 从一句目标，到一场协作

比如：“审查当前项目，让另一位 Agent 独立复核，只报告有证据的问题。”

在 Wave Flow 中，你可以：

1. **先看方案，再决定执行。** 通过对话生成和调整工作流，也可从内置预置开始：只读代码审查、深度调研、深度代码审查。
2. **按阶段掌握进度。** 阶段 → 执行者层级展示协作分工，查看每个 Agent 的状态、流式正文和工具活动。
3. **需要你时，再接手。** Agent 显式请求人工协助，你提交答案后，由原 Agent 确认继续；也可主动暂停或停止。
4. **结束之后，有据可查。** 查看结构化交付与历史执行尝试；中断后显式恢复，不悄悄重跑。

写入类 Workflow 使用一个受管 Git worktree：同一执行的所有写 Agent 共享同一目录，改动直接保留在该 worktree 的未提交文件里，无需提前填写成果文件路径。宿主不做冲突检测或合并，同一文件后写覆盖先写，因此任务应按模块/文件分区。执行完成后宿主**不创建 commit、不保存快照、不写主工作区、不移动分支**；结果就是该 worktree 的当前内容，用户自行查看、修改、提交或清理，宿主不对后续改动负责。

## 为什么是 Wave Flow？

### 长任务，靠流程推进，不靠模型记住计划

工作流明确阶段、依赖、并行与完成条件，支持顺序、并行、流水线和动态调用。用明确的执行规则减少长程任务的编排漂移；模型仍有发挥空间，但不需要独自记住整个执行计划。底层采用 TypeScript 编排，兼顾灵活性与可控性。

交付须经过 Schema 校验和持久化记录，Agent 的一句“完成了”不能替代完成证据。流程可控不代表答案必然正确，执行完成也不等于目标已验收。

### 不押注一个 Agent，让不同 CLI 各展所长

把 Codex、DeepSeek Harness、Claude Code 放进同一条 Workflow：独立研究、交叉审查，再比较证据、择优汇总。也可以结合各自模型、工具与 CLI 能力分配工作，让擅长分析的分析、擅长实现的实现。

每个 Worker 绑定独立真实 ACP 会话，使用你选择的本机 CLI 及其默认模型。多 CLI 协作利用不同模型与 Harness 的互补性，降低单一路径的盲区；当前由用户分配 CLI，不提供自动模型路由。

### 一份技能库，执行时注入所有会话

在 `~/.wave-flow/skills/<name>/SKILL.md` 维护自己的 skill，Wave Flow 会在每次主控与 Worker 会话启动时以软链投影注入，不写入、不覆盖原生 CLI 目录；单独使用 codex/claude/dsh 时完全不受影响。设置 → 技能 可以从本机各 CLI 的技能目录发现并导入，也可以上传单个 `skill.zip`；导入的 skill 会合并进主控斜线菜单（Codex 为 `$name`，Claude/DSH 为 `/name`），新建或空闲重开的主控会话即可使用；导入前会校验 SKILL.md、frontmatter、软链、同名冲突与 ZIP 路径/大小，导入是复制且不覆盖已有同名 skill。空库不改变任何行为；库非空但当前 CLI 没有已验证的注入能力时会直接拒绝启动，而不是静默忽略。

### 方案可以商量，执行权始终在你手里

通过对话调整待执行方案，版本记录保留每次变化；放弃方案不丢掉任务和对话。主控负责提案，用户确认才授权运行。执行中可以查看进度、提供人工协助、暂停或停止，中断后显式恢复原执行。

> 一个新 Task 持有一条持续演进的工作流链。执行后可根据反馈修订源码、输入或 CLI 配置；确认新版后创建新的 Execution，在已安全交接的当前现场重新工作。原版本恢复仍属于同一 Execution，不提供任意节点回滚或跨版本自动重放。

### 执行与证据也有明确的故障边界

停止或退出会同时撤销排队与初始化中的启动许可，不会在新任务已停止后继续启动 Worker。Journal 写入失败会阻止后续追加，并保留首个错误；停止流程仍尽力通知真实 Worker。writer 在创建进程前先记录启动意图，崩溃后无法核验时拒绝直接恢复，避免重复写入。

大批量成果路径采用流式收集，不截断为不完整证据；变更列表支持分页审阅。图片附件单张上限 10MB，并在读取前后复核文件身份与实际字节数。执行详情采用单请求轮询，避免较大证据响应造成页面持续加载。

## 下载与安装

当前版本：`v0.2.10`，支持 macOS 12+ / Apple Silicon。可在终端一键安装：

```sh
curl -fsSL https://oliver-ysq.github.io/wave-flow/install.sh | sh
```

也可以从 [Releases](https://github.com/Oliver-Ysq/wave-flow/releases) 下载 `Wave.Flow_0.2.10_aarch64.dmg`，或从源码构建：

```sh
bun install
bun run desktop:dev   # 开发模式
bun run desktop:build # 生成 release 安装包
```

产物位于 `src-tauri/target/release/bundle/`。开发机没有证书时使用 ad-hoc 签名；正式分发仍需配置 Developer ID，并验证 hardened runtime、Bun JIT entitlement 与公证。Intel 构建需要另加目标并验证。

## 特别适合这些任务

- **广覆盖、重证据的探索：技术调研与大范围 CR。** 多 CLI 独立探索不同方向，再集中复核与比较，减少单一模型或 Harness 的遗漏和偏差。
- **多阶段、强约束的交付：需求分析 → 代码开发 → 自测 → 代码 CR。** 将阶段交接与验证纳入工作流，让开发和审查各有分工，不把整条交付链只写在 Prompt 里。
- **重复多、标准统一的治理：依赖升级、API 迁移与跨模块规范修正。** 按模块拆分任务，独立处理后统一验证与复核。并行写入共享同一 worktree，须按模块/文件分区，不把目录分离当作安全隔离。

## 快速开始

运行桌面应用，在项目里直接描述目标，或选择“预置工作流”“本地工作流”。本地来源须是项目内受信任 `.ts` 文件，声明纯字面量 `meta.inputSchema` 对象参数 Schema；预检只读取、不会运行脚本。保存方案后，在方案页确认参数、CLI 和必要的 Git 授权才启动。

内置预置工作流：

- **代码审查**：两个顺序只读 Worker，先审查再独立复核，只检查指定范围。
- **深度调研**：计划 Agent 拆解研究问题并等你确认，再并行多源调研；每条结论由独立核验员重新打开原始来源复核，交叉检查矛盾与单一来源风险；`deep` 模式按证据缺口做第二轮定向补证，最后经红队审查修订，产出带引用与置信度分级的报告。需要 Worker 的 CLI 具备检索与浏览能力。
- **深度代码审查**：先摸底变更面、模块结构与仓库审查规范，再由六个专项审查员（正确性、安全、并发与状态、错误处理与资源、接口与数据兼容、意图与测试）并行审查；每个发现由独立复核员重新打开源码逐条核实并剔除误报，再交叉裁决去重排序，盲区扫描披露未被覆盖的高风险文件。全程只读，不运行构建或测试。

在输入框输入 `/` 可打开命令菜单：`/wave-flow` 让主控基于本次目标生成 Workflow 草案；草案是标准 ESM 作者模块，用户可审批执行，或在任务中“保存并接管”为项目内 `.ts` 本地来源。技能由当前主控 CLI 通过 ACP 广告提供。选中命令会显示为不带前导 `/`、无底色、强调色加粗的图标块，可以连续插入多条，按 Backspace 在块边界整条删除；选择只改写输入框，不会自动发送。当前不提供 `/compact`。

还没有项目时，新建任务页直接给出“新建项目”入口并锁定输入；选择项目后才显示来源和可输入区域。最新未查看的待确认方案会在输入框上方提示“第 N 版方案待确认”，点击直接打开；任务顶部的“当前工作与历史”条把状态、主操作和历史入口收拢。最近一次执行在对话中显示为一张卡片，旧执行只保留一行历史，不重复“已启动/已结束”两条记录。

执行结束后查看执行总结。需要调整时，通过对话修订生成方案、准备模板参数新版本，或编辑本地文件后重新预检；仅切换 CLI 可选择“保留源码，准备 CLI 配置新版本”。写修订自动接续同一 Task 最近一次写执行的共享 worktree 并冻结交接 HEAD；新版启动前重新核验现场，旧结果不自动复用。归档后只读。

## 当前边界

Wave Flow 仍在早期开发，欢迎试用，也请留意：

- Workflow 是 ESM 作者模块；本地文件与主控生成稿共用同一格式、加载器和作者 API。主控不能直接写项目文件；生成的模块只有经用户审批或显式保存接管后才进入项目。生成模块与手写 Workflow 同等受信任，以当前用户本机权限运行，不提供 Workflow JavaScript 的 OS 级沙箱。不支持 URL 下载工作流、可视化流程编辑、远程控制或云同步。
- 主控默认开启感知模式：使用用户原生 CLI 配置与工具（skill/MCP/CLI）读取信息，OS 只拒绝写入当前项目与 Engine 状态目录，因此项目文件不会被主控修改；修改项目仍必须提出 Workflow 并由用户确认。设置中可关闭感知模式，关闭后主控回到私有隔离 Home、全量写隔离与四个窄工具。项目保护只覆盖当前项目，不覆盖其他项目、其他 Git 仓库或用户 Home；网络与外部系统副作用不被文件策略证明，主控仍可读取凭据并调用已登录工具。感知模式禁止新建硬链接；启动前已存在的项目外硬链接别名不在路径沙箱可枚举范围内，需自行清理。Worker 使用可信原生 CLI 配置与权限，不额外施加 Wave Flow OS 文件隔离。worktree/cwd 只分离正常工作现场，不能阻止 Worker 修改其他目录、其他 worktree、共享 Git 或凭据；任务意图不是安全保证。一次执行只创建一个共享受管 worktree，所有写节点共用同一目录；宿主不做冲突检测或合并，同一文件后写覆盖先写，因此任务应按模块/文件分区。受管 worktree 的文件内容不证明工作区外影响，也不替代敏感内容审阅。
- 执行完成后宿主不保存任何成果快照或证据 ref，也不创建 commit：结果只保留在受管 worktree 的当前文件里，不写入主工作区。之后由用户自行查看、修改、提交或清理；清理该 worktree 会一并删除其中的未提交内容。原生 CLI 仍使用 `~/.codex`、`~/.dsh`、`~/.claude`；配置与凭据也可能被模型工具修改。
- Kimi CLI 支持已暂时下线：设置页不提供检测、验证、默认主控或 Worker 分配入口，历史 Journal/Execution 记录仍只读可查；恢复需重新接回并验收，旧记录不会自动重写。托管技能库只负责把 skill 文件投影进会话，不供给 `metadata.requires.bins` 声明的二进制、登录态、网络或 MCP；设置页会对 `requires.bins` 做只读 PATH 诊断并提示缺失项，但不会自动安装依赖或修改 PATH；Codex 的额外根会同时扩展其 sandbox 写根，投影目录因此只放在 Wave Flow 会话 scratch 内。Worker 按可信原生 CLI 模型可以修改技能库，从而影响后续主控会话，这不是新增的 OS 隔离边界。库内容变化会使旧 completed 节点在 Replay 时不再复用。
- DeepSeek Harness 与 Claude Code 均已完成主控与 Worker 双角色真实验收，可在设置页设为默认主控。默认感知模式直接使用用户原生配置（skill/MCP/CLI/登录态可用）；关闭感知模式时主控使用各自私有隔离 Home：Claude 只继承认证/模型 env（用户 hooks/permissions 不进入主控）；DeepSeek Harness 使用出厂 profile 骨架且清空用户 patch，凭据仅软链引用。DeepSeek Harness 需在 `$DSH_HOME` 配置 provider key，且其 CLI 要求 Node ≥ 24 运行时（Node ≤ 22 下会静默退出，无任何输出）。Claude Code 的验收验证的是 harness 兼容性（Claude Code 2.1.304 + claude-agent-acp 0.94.0），模型侧由用户 `~/.claude/settings.json` 的认证配置决定（验收使用 Anthropic 兼容端点，非 Anthropic 模型）。
- 完整总结、当前现场补充及 writer 安全交接是修订启动的前置条件。新版所有实际节点重新工作，不跨 Execution 缓存旧完成结果。新 Task 使用单链契约，旧多卡记录不自动迁移。
- 中断恢复只复用同一执行内严格匹配的已完成前缀；不会回滚文件或撤销外部副作用。
- Worker 原生会话持续五分钟无实质进展（正文/工具/计划事件）时，执行器记录一条停滞诊断提示，不自动中断、不 cancel、不重发任务；等待人工答案、用户暂停与控制操作不计入窗口，唯一出口是用户显式停止。静默和 read-only 意图都不能证明没有副作用。
- 原版恢复须先完成执行总结并核验现场；Git 现场变化会要求独立影响面补充和重新确认。未交接 writer、未保存改动或旧成果不一致会阻止恢复，不自动回滚。Git 指纹只覆盖可核验文件，不证明外部系统状态。
- 宿主不保存成果快照：执行完成后结果只保留在受管 worktree 的当前文件里；未知 writer 退出仍会阻止交接。
- 工作台与执行引擎运行在本机；模型请求仍由所选 CLI 发送给其服务商，不代表离线推理或数据不出本机。
