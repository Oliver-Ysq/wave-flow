# Wave Flow

**让任务有章可循，让不同 Agent 发挥所长。**

Wave Flow 是一个本机运行的 AI Agent 工作流桌面应用。用对话描述目标，让主控提出方案；确认后，由真实的 Codex / Claude Code Agent 分阶段执行（DeepSeek Harness 与 Kimi CLI 支持已暂时下线，历史记录仍可查看）。你可以随时查看进度、回答问题或停止任务。

把任务交给可控的流程，把不同工作交给合适的 Agent。不必让一段越来越长的对话，承担从规划到交付的所有事情。

## 从一句目标，到一场协作

比如：“审查当前项目，让另一位 Agent 独立复核，只报告有证据的问题。”

在 Wave Flow 中，你可以：

1. **先看方案，再决定执行。** 通过对话生成和调整工作流，也可从内置预置开始：只读代码审查、深度调研、深度代码审查。
2. **按阶段掌握进度。** 阶段 → 执行者层级展示协作分工，查看每个 Agent 的状态、流式正文和工具活动。
3. **需要你时，再接手。** Agent 显式请求人工协助；你提交答案后，宿主确认答案已交付，原 Agent 再继续。也可主动暂停或停止。
4. **结束之后，有据可查。** 查看结构化交付与历史执行尝试。中断后可以只恢复受影响的节点：同一 Engine 内续用原 ACP 会话；Engine 重启后先确认旧进程已经退出，再续用原会话，只重跑真正中断的部分，已完成部分按证据复用。

写入类工作流在独立的受管 Git worktree 中执行，结果保留为未提交改动。宿主不会自动 commit、不会写回主工作区，由你决定如何查看、修改、提交或清理。并行写需按模块或文件分区，宿主不做冲突检测与合并。Engine 异常退出时，其托管的 Worker 进程由独立 supervisor 终止；恢复前还会核验旧写者确已退出。

## 为什么是 Wave Flow？

### 长任务，靠流程推进，不靠模型记住计划

工作流明确阶段、依赖、并行与完成条件，支持顺序、并行、流水线和动态调用。用明确的执行规则减少长程任务的编排漂移；模型仍有发挥空间，但不需要独自记住整个执行计划。底层采用 TypeScript 编排，兼顾灵活性与可控性。

交付须经过 Schema 校验和持久化记录，Agent 的一句“完成了”不能替代完成证据。

多 Agent 默认通过自包含 prompt 与结构化结果交接。多轮顺序接力的工作现场较复杂、交接内容较大时，Workflow 可以按需让前一个 Agent 在共享 worktree 生成或更新 `todo.md`，记录目标、已实现内容与已解决的问题，后一个 Agent 读取后再核对实际现场。它只是可选的交接材料，不是完成判据；并发分支不得共同写同一文件，可使用独立文件，或在汇合后由单个节点统一整理。

### 不押注一个 Agent，让不同 CLI 各展所长

把 Codex 和 Claude Code 放进同一条 Workflow：独立研究、交叉审查，再比较证据、择优汇总。每个 Worker 绑定独立真实 ACP 会话，使用你选择的本机 CLI 及其默认模型；多 CLI 协作降低单一路径的盲区。

### 一份技能库，执行时注入所有会话

在 `~/.wave-flow/skills/<name>/SKILL.md` 维护自己的 skill，Wave Flow 会在主控与 Worker 会话启动时以软链投影注入，不写入原生 CLI 目录；单独使用 codex/claude/dsh 时不受影响。设置 → 技能 可以从本机各 CLI 的技能目录发现并导入，也可上传单个 `skill.zip`。空库不改变任何行为。

### 方案可以商量，执行权始终在你手里

通过对话调整待执行方案，版本记录保留每次变化；放弃方案不丢掉任务和对话。主控负责提案，用户确认才授权运行。主控使用你的原生 CLI 配置读取信息，但不能直接修改项目文件；修改项目仍须走 Workflow 并由你确认。执行中可以查看进度、提供人工协助、暂停或停止，中断后显式恢复原执行。

> 新 Task 持有一条持续演进的工作流链。执行后可修订源码、输入或 CLI 配置；确认新版后创建新的 Execution，在已交接的现场重新工作。原版本恢复仍属于同一 Execution，不提供任意节点回滚。中断恢复以节点为单位：同一 Run 中一个节点中断，不会让整条流程重跑。

## 下载与安装

当前版本：`v0.6.0`，支持 macOS 12+ / Apple Silicon。

### v0.6.0 重要变更

- Worker `block` 表单新增整张表单共享的“其他意见（可选）”多行输入，最长 4000 字。补充意见作为独立 `userNote` 与 Schema 答案一起耐久保存并交付原 Agent，不会注入 `answerSchema` 或 ACP accept content。
- 答案与意见按 block 隔离草稿，“暂不”只收起表单，重新打开保留输入；“继续”和“暂不”统一收进底部主次操作区。
- 旧 Journal 没有 `userNote` 仍可正常读取；同一 block 的幂等回答同时核答案与意见，任一冲突都拒绝覆盖。

### v0.5.0 重要变更

- 新 Workflow 不再提供 `decisionGate`。任何 Worker 无法独立解决、需要用户补充信息、裁决或授权的问题，统一由原 Worker 在同一会话中 `block`；回答后逐项复核，仍有歧义则继续 `block`，全部解决后才能继续。
- 普通产品缺陷仍通过修复与复验处理，只有用户也无法解除的硬阻塞才允许终止，不能用自定义 `status: "blocked"` 代替人工表单。
- 旧 Journal 中的脚本 gate 事件不再兼容，重开含此类事件的档案会明确拒绝；升级前请自行清理这些历史事件。Worker `block` 事件与其他执行事实保持原语义。

运行前提（Wave Flow 不内置、也不自动安装这些工具）：

- **至少一个受支持的本机 CLI**：Codex 或 Claude Code，已自行安装并用你的账号登录。设置页只扫描与验证本机已有安装；模型请求由所选 CLI 发送给其服务商。DeepSeek Harness 支持已暂时下线。
- **系统 Git**：受管写执行、现场核验与 worktree 交接依赖它。macOS 上由 Xcode Command Line Tools 提供。
- **系统 `unzip`**：仅用于导入单个 `skill.zip`，macOS 自带。
- **Claude Code** 的模型与认证由你的 `~/.claude/settings.json` 决定。
- 可选：`ripgrep`（`rg`）只影响主控的只读全文搜索。

原生 CLI 仍使用 `~/.codex`、`~/.dsh`、`~/.claude`；其配置与凭据也可能被模型工具修改。Codex Worker 使用支持人工表单的 `agent` 模式，并保留 `danger-full-access` 沙箱配置；不要改成会立即拒绝非空人工表单的 `agent-full-access`。

可在终端一键安装：

```sh
curl -fsSL https://oliver-ysq.github.io/wave-flow/install.sh | sh
```

也可以从 [Releases](https://github.com/Oliver-Ysq/wave-flow/releases) 下载 `Wave.Flow_0.6.0_aarch64.dmg`，或从源码构建：

```sh
bun install
bun run desktop:dev   # 开发模式
bun run desktop:build # 生成 release 安装包
```

产物位于 `src-tauri/target/release/bundle/`。正式分发需配置 Developer ID，并验证 hardened runtime、Bun JIT entitlement 与公证。

## 特别适合这些任务

- **广覆盖、重证据的探索：技术调研与大范围 CR。** 多 CLI 独立探索不同方向，再集中复核与比较，减少单一模型的遗漏和偏差。
- **多阶段、强约束的交付：需求分析 → 代码开发 → 自测 → 代码 CR。** 将阶段交接与验证纳入工作流，让开发和审查各有分工。
- **重复多、标准统一的治理：依赖升级、API 迁移与跨模块规范修正。** 按模块拆分任务，独立处理后统一验证与复核。

## 快速开始

运行桌面应用，在项目里直接描述目标，或选择“预置工作流”“本地工作流”。本地来源须是项目内受信任的 `.ts` 文件；预检只读取、不会运行脚本。确认参数、CLI 与必要的 Git 授权后启动。

内置预置工作流：

- **代码审查**：两个顺序只读 Worker，先审查再独立复核，只检查指定范围。
- **深度调研**：计划 Agent 拆解问题并等你确认，再并行多源调研；结论由独立核验员重新打开原始来源复核，最后经红队审查修订，产出带引用与置信度分级的报告。需要 Worker 的 CLI 具备检索与浏览能力。
- **深度代码审查**：先摸底变更面、模块结构与仓库审查规范，再由六个专项审查员并行审查；每个发现由独立复核员重新打开源码核实并剔除误报，最后交叉裁决去重排序。全程只读，不运行构建或测试。

输入 `/` 可打开命令菜单：`/wave-flow` 让主控基于本次目标生成 Workflow 草案；草案是标准 ESM 作者模块，可审批执行，或“保存并接管”为项目内 `.ts` 本地来源。

执行结束后查看执行总结。需要调整时，可修订生成方案、准备模板参数新版本，或编辑本地文件后重新预检。归档后只读。

## 说明

- **完成上报能否扛住上下文压缩，取决于所用 CLI 是否声明客户端系统提示。** Wave Flow 会把“必须调用完成工具”的协议作为会话级系统提示下发（ACP `systemPrompt`）。声明该能力的 CLI 在上下文压缩后仍保留这条协议；未声明的 CLI 继续把协议写在任务提示里，行为与旧版本一致。
- **不会静默降级。** 未声明能力时不发送；声明了但应用失败会明确报错，不会出现“发了却被忽略”而无人察觉的情况。
- **该字段目前是 ACP 预览能力。** 上游若调整字段或语义，Wave Flow 会退回内联协议路径，并在升级适配器时重新做真机验证。完成判定始终只由完成工具、结果 Schema 校验与 Journal 持久化决定，不受该字段影响。
